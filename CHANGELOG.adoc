=== [Unreleased]

==== Added

* M0: Zig 0.17.0 scaffold, vendored SQLite 3.50.4 amalgamation (FTS5,
  THREADSAFE=2, no load-extension) built by `zig cc`, hand-written FFI
  externs, `Containerfile` with a checksum-pinned toolchain.
* M1: item model, adapter interface (`Adapter`, `Registry`, `Cond`,
  `Outcome`, `FailureClass`), tolerant XML DOM (XXE-safe), encoding
  detection and conversion, tolerant date parsing, RSS 2.0 / Atom / RDF feed
  adapter, guid/id then link+date de-duplication, recorded and hand-made
  fixtures.
* M2: scheduler over an injected clock and PRNG: intervals, jitter,
  exponential backoff, `Retry-After` floor, startup spread, no busy loop.
* M3: NDJSON log as source of truth, SQLite state, FTS5 trigram index
  rebuilt from the log, crash replay via `meta.indexed_offset`, lock file.
* M4: HTTP(S) transport (select-based wall-clock timeout, manual redirects,
  size cap, certificate probe), JSON config, engine, daemon with signals,
  CLI.
* M5: monitor adapter: up/down transitions (DOWN after two failures, first
  success silent), content-change hash with hourly rate limit, TLS leaf
  expiry, robots.txt (RFC 9309); `monitors` command.
* M6: localhost-only web UI (list, search, item, read marks, status) with
  Host-header allowlist, Origin check on POST, CSP and no JavaScript;
  `web.allow_non_loopback` required for a non-loopback bind; end-to-end test.
* M7: repository minted from `rsr-template-repo` (deed, roadmap,
  provisioning, gates); `zig-ci.yml` runs format check, unit tests, static
  release build, config smoke and both `Containerfile` stages; Zig pinned to
  0.17.0 in `mise.toml` / `mise.lock`.

==== Fixed

* Review findings on the import PR (Codex), each with a test where one was possible:
  an RSS channel without a title no longer panics the daemon; `deepText` keeps
  mixed content in document order; mistyped booleans in the config are rejected
  instead of silently taking the default; `heron fetch NAME` fails on an unknown
  name; a stale robots.txt `blocked` flag is cleared when `check_robots` is turned
  off and the cached robots.txt is no longer truncated below the fetch cap; the
  web UI accepts its own bound address in Host, clamps the page number (no u32
  overflow), does not mark items read on HEAD, refreshes its cached log length
  before reading a record the poller appended, and bounds each connection with a
  10 s socket deadline; records larger than the replay limit are refused at
  ingest; relative Atom/RSS links are resolved against the feed URL; the scratch
  image ships `/data` owned by the runtime UID; the template Tier-A image
  (`build/container/Containerfile`) now builds and runs heron.
* Second review round: unknown config keys and wrongly typed integers are
  rejected (the documentation already promised the first); a failed SQLite
  transaction after a durable log append no longer lets the next ingest skip
  those records; `plainText` treats a bare `<` as text; change detection
  decodes character references before hashing; the transport reports the
  post-redirect URL (used as the base for relative links) and the Location of
  an unfollowed redirect; with `check_robots` on, the monitor steps through
  redirects itself and refuses a hop to another origin before fetching it;
  the compose stack mounts a config, publishes the UI on host loopback only
  and drops the unusable health check; `.dockerignore` no longer hides the
  Tier-A entrypoint from its own build.
* Third review round: network-derived text printed by the CLI (`list`,
  `search`, `show`, `sources`, `monitors`) has control characters replaced,
  so a feed cannot inject terminal escape sequences; `check-config` rejects
  non-string values for string fields and source types no adapter serves;
  a log replaced by a shorter one clears the derived index before
  reindexing; web pagination keeps the source filter; `24:mm` timestamps
  other than `24:00:00` are rejected; `heron fetch` cannot overflow its
  failure counter; the compose build context is the repository root; the
  documented monitor defaults and robots.txt behaviour now match the code.

==== Changed

* Renamed to heron-polyfeed-reader: binary `heron`, environment
  `HERON_CONFIG` / `HERON_DATA`, lock file `heron.lock`.
* Seven source files reformatted by `zig fmt` 0.17 (`@intFromEnum` →
  `@backingInt`, literal layout); no behaviour change, 85/85 tests still pass.
