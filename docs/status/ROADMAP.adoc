= heron-polyfeed-reader Roadmap

The STATE journal of heron-polyfeed-reader: milestones, blockers and next
actions. Phase and maturity are not recorded here; they live in the repo deed,
`heron-polyfeed-reader_chora.deed`, in the `(status …)` and `(maturity …)`
clauses (`just state-phase` prints both).

This file absorbs the handoff note (`HANDOFF.md`, written 2026-10-19) that
travelled with the M0–M6 import on 2026-10-27. That note is retired here; its
build and test instructions moved to `README.adoc` and `CONTRIBUTING.adoc`.

== Current status

Milestones M0–M6 are complete and imported with their signed commit history.
Ground truth at import (2026-10-27, Zig 0.17.0 exactly, x86_64 Linux host):

* `zig build test --summary all`: 85/85 tests pass at import; 94/94 after
  the four review rounds (see below).
* `zig build -Doptimize=ReleaseSafe` and the static musl build both succeed.
* `zig fmt --check` was NOT clean on seven files (Zig 0.17 renames
  `@intFromEnum` to `@backingInt` and re-wraps two literals); the formatter was
  applied at import so that `just lint` passes.
* Idle RSS ~8 MB (ReleaseSafe, 24 feeds + 6 monitors + web UI) was measured
  before import over one ~45 s window; not re-measured since.

=== Import review (2026-10-27 to 2026-11-04)

The import merged to `main` as hyperpolymath/heron-polyfeed-reader#3
(squash, 2026-10-27). Codex reviewed every push: 45 findings over four
rounds, each traced to a real input before it was fixed, all fixed with
tests, none declined. The fourth round (8 findings) was posted as #3 merged
and is fixed on a follow-up PR. Among them: panics or ReleaseSafe traps
on untrusted input (title-less RSS channel, page-number overflow,
out-of-range `cert_warn_days`), a use-after-free of configuration error
text, terminal-escape injection through feed titles printed by the CLI, a
cross-site GET that marked items read, mixed-content text order, index/log
consistency (stale read-only log length, replay limit, failed-commit replay,
truncated-log reindex), strict configuration (unknown keys, mistyped values,
unknown adapter types, unusable `web.bind`), robots.txt across redirects, and
the template container stacks (Tier-A image, compose and selur configs).
SonarCloud's quality gate passed. CodeRabbit did not review: the import's
216 files exceed its 100-file limit and the account had no credits.

== Blockers

. *Clade is UNASSIGNED* in the deed. Choosing it is the owner's act (the
  template says so); `just validate-rsr` fails until it is chosen. The
  ecosystem `:position-type` is UNASSIGNED for the same reason.
. *Code-owner review of your own PR.* `main`'s Branch-Floor ruleset requires
  a code-owner review, and CODEOWNERS names only `@hyperpolymath`, who also
  authors these PRs; GitHub never counts an author's own review. The owner
  merged #3 themselves. Every later PR from this account meets the same
  wall unless a second code owner (a person or a team) is added or the rule
  is relaxed for solo repositories; that is an estate-wide question for
  `standards`, not this repo alone.
. *Commit signatures.* The M7 commits were signed by the cloud session's
  key, not the owner's `id_ed25519_signing`; `main` holds the squash commit
  GitHub made. The eleven milestone commits keep their own signatures in
  #3's commits, which GitHub keeps at `refs/pull/3/head` (a squash
  flattens them out of `main`; the source branch was deleted on merge).
. *Idris2 ABI seam.* `just test` and `just build` run every detected
  language. The template's `src/interface/abi.ipkg` (Idris2) is detected
  alongside `build.zig`; without `idris2` on PATH the Zig steps pass but the
  recipe exits non-zero. Decide whether the seam stays (then provision
  `idris2` via pack, as the template expects) or whether this project opts
  out (then `validate-rsr`, which hard-requires `src/interface/{abi,ffi,generated}`,
  needs a ruling).
. *mise.lock was edited by hand* for the Zig 0.17.0 pin (no `mise` in the
  import session). Checksums are the official ones from
  `ziglang.org/download/index.json`; re-lock with `just toolchain-refresh` to
  confirm.

== Known gaps / untested

* Never run against live public sites; every HTTP test uses a local fixture
  server.
* Certificate probe verified only against a self-signed certificate.
* Web UI exercised via raw HTTP, not a browser; no search pagination.
* x86_64 Linux only; no soak test; RSS measured once.
* The adapter interface is meant to take NNTP, Gopher, Gemini, ActivityPub
  and AT Protocol without core changes; unproven until M8.

== Design decisions made without owner input (revisit freely)

* JSON config, no YAML; web UI off unless configured; default bind
  `127.0.0.1:8484`; a non-loopback bind needs `web.allow_non_loopback`.
* Web UI: Host-header allowlist (DNS rebinding), Origin check on POST, CSP,
  no JavaScript, http(s)-only links, its own SQLite connection.
* Monitor alerts are stored as items of kind `alert`; the first success is a
  silent baseline; DOWN after two failures; change alerts rate-limited to
  one per hour.
* WebSub deliberately not implemented.
* Binary `heron`, environment `HERON_CONFIG` / `HERON_DATA`, lock file
  `heron.lock`.
