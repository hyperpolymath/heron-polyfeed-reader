= Proof Status — heron-polyfeed-reader

Status words are the closed vocabulary of the estate PROOF-POLICY §5:
PROVEN, PROVEN-WITH-AXIOMS, TESTED (with bounds), ASSUMED, OPEN. Every row
below was run, not read; the date and toolchain are on the row.

== Summary

heron owns one proof of its own: `seamAgreesWithHeader` in
`src/interface/Abi/Sqlite.idr` (SEAM-4). The files under
`verification/proofs/` are the RSR template's worked examples about example
types (a bounded natural number, a toy expression language). They are kept
compiling by `just proof-check-all`, and they are correct, but they prove
nothing about heron. The mathesis estate census reads each repository's
`main`, so it will count the SEAM-4 proof only after this lands there.

heron's real formal boundary is its SQLite C API: 22 functions and 8 integer
constants. They are declared in exactly one place,
`src/interface/generated/sqlite_c.zig`, which is rendered from the Idris2
description in `src/interface/Abi/Sqlite.idr` and never edited by hand.

== heron's own obligations

[cols="1,4,1,4", options="header"]
|===
| ID | Obligation | Status | Evidence

| SEAM-1
| The 22 SQLite declarations agree with `vendor/sqlite/sqlite3.h` (SQLite
  3.50.4): same functions, same arity, and the same ABI shape for every
  parameter and result (32-bit int, 64-bit int, pointer, no value); and the
  8 integer constants equal the header's values.
| TESTED
| Every Zig CI run: `scripts/check-sqlite-seam.sh header` compares the
  generated file with `zig translate-c vendor/sqlite/sqlite3.h` (Zig 0.17.0)
  and refuses an SQLite declaration anywhere else in `src/`. Bounds: this
  SQLite version, x86_64-linux, ABI shape rather than C-level type identity
  (a `char *` and an `int *` are both "pointer"). Seen failing on six
  deliberate corruptions (wrong width, wrong constant, wrong arity, an unknown
  function, a hand edit, a stray declaration) on 2026-11-09.
  `SQLITE_TRANSIENT`, a pointer sentinel kept in `src/sqlite.zig`, is not
  covered.

| SEAM-2
| SQLite behaves as its documented C API.
| ASSUMED
| Third-party code (PROOF-POLICY §1.1).

| SEAM-3
| The `setpriority` declaration in `src/daemon.zig` matches the C library.
| OPEN
| Not checked.

| SEAM-4
| One source for the SQLite boundary. `Abi.Sqlite` describes it once; the
  type checker proves each function's ABI shape equals a table of
  `sqlite3.h`; `SeamGen` renders the Zig file from the same description.
| PROVEN (shape agreement); TESTED (rendering)
| `seamAgreesWithHeader : agrees seam header = True` is `Refl`, accepted by
  Idris2 0.7.0 with `%default total`; a corrupted table entry is rejected.
  `just seam-check` (also in `just ci`) re-renders the file and fails on any
  difference. That rendering check needs idris2, so it runs locally, not in
  GitHub CI, until idris2x provides Idris2 there. The table itself is
  transcribed, which is why SEAM-1 checks the rendered file against the
  header directly.
|===
