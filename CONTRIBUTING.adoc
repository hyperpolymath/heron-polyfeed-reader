= Contributing — heron-polyfeed-reader
:toc: left

`heron` is a small Zig daemon with no dependencies beyond the vendored SQLite
amalgamation. Most changes are a unit test plus the code that makes it pass.

== Local-dev setup

Needs *Zig 0.17.0 exactly*. `std.Io`, `std.http` and the TLS APIs changed from
0.15/0.16; check against the installed `std`, not against older examples.

[source,bash]
----
git clone https://github.com/hyperpolymath/heron-polyfeed-reader.git
cd heron-polyfeed-reader

# Toolchain: mise pins zig = "0.17.0" (mise.toml / mise.lock)
just setup                           # or: mise install
just doctor                          # PASS/WARN/FAIL with codes

# The project's own loop
zig build test --summary all         # 85 unit tests; fixtures under src/testdata/
zig fmt --check build.zig src        # what `just lint` runs
zig build -Doptimize=ReleaseSafe     # zig-out/bin/heron

# Containerised (podman or docker)
podman build -f Containerfile --target test -t heron-test .
----

`just test` / `just build` / `just lint` go through the estate provisioning
library and run every detected language; the template's Idris2 ABI seam under
`src/interface/` is detected too, so those recipes also want `idris2` (from
pack). `zig build …` alone is enough for the project.

== Conventions to keep

* SPDX headers on every source file: `SPDX-License-Identifier: MPL-2.0` and
  `SPDX-FileCopyrightText: 2026 Jonathan D.A. Jewell` (code); `CC-BY-SA-4.0`
  for prose.
* No Python in the repo (estate language policy; see `CLAUDE.md`). FFI is
  hand-written Zig externs (`src/sqlite.zig`), not generated bindings:
  `@cImport` no longer exists in Zig 0.17.
* Containerise build and tests by default; the toolchain is pinned by version
  and SHA-256 in the `Containerfile` and in `.github/workflows/zig-ci.yml`.
  Change the pin in both, and in `mise.toml` / `mise.lock`, together.
* `src/vendor/tls_client.zig` is a patched copy of std's TLS client (`[sfr patch]`
  markers: `host.sni_only`, `leaf_not_after`). Re-sync it whenever Zig is
  upgraded; `src/vendor/NOTICE` says how.
* All HTTP tests use the local fixture server (`src/localserver.zig`); never
  make a test depend on a live site.
* Commit at each milestone, with the milestone in the subject
  (`M8: …`). Record anything decided without the owner's input in
  link:docs/status/ROADMAP.adoc[the roadmap] so it can be revisited.
* Report faithfully: say what was run and what passed; a skipped check is
  reported as skipped, never as green.

== How to contribute

=== Reporting bugs

*Before reporting:*

. Search existing issues.
. Check if it is already fixed in `main`.
. Determine which perimeter the bug affects.

*When reporting*, use the
link:.github/ISSUE_TEMPLATE/bug_report.md[bug report template] and include:

* Clear, descriptive title
* Environment details (OS, versions, toolchain)
* Steps to reproduce
* Expected vs actual behaviour
* Logs, screenshots, or minimal reproduction

=== Suggesting features

*Before suggesting:*

. Check the link:docs/status/ROADMAP.adoc[roadmap] if available.
. Search existing issues and discussions.
. Consider which perimeter the feature belongs to.

*When suggesting*, use the
link:.github/ISSUE_TEMPLATE/feature_request.md[feature request template]
and include:

* Problem statement (what pain point does this solve?)
* Proposed solution
* Alternatives considered
* Which perimeter this affects

=== Signed commits

Every commit that reaches the default branch must be signed; a ruleset refuses
unsigned pushes. Estate policy:
https://github.com/hyperpolymath/standards/blob/main/docs/SIGNING-POLICY.adoc[SIGNING-POLICY].

* **People and interactive agents** sign with an SSH key registered on GitHub
  as a *signing* key (`gpg.format=ssh`, `user.signingkey=<key>.pub`,
  `commit.gpgsign=true`). The committer email must be verified on that account.
* **Apps, bots and workflows** never `git push` local commits. They write
  through the API (`createCommitOnBranch` or the estate `signed-push` action)
  so that GitHub signs each commit.
* Merge PRs with **squash**. The ruleset checks every commit on the PR branch,
  not just the result, so one unsigned commit blocks the merge. Re-create such a
  branch with signed commits (`git cherry-pick -S`) and open a new PR.
  Rebase-merge replays commits unsigned and is disabled.
